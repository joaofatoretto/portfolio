# Languages: English and Brazilian Portuguese

English is the site. Portuguese (pt-BR) is a full mirror at `/pt-br/...` for people whose browser asks for Portuguese.
If anything about Portuguese fails, the visitor gets English.

## URLs

| English | Portuguese |
| --- | --- |
| `/` | `/pt-br` |
| `/work/<slug>` | `/pt-br/work/<slug>` |
| `/hire` | `/pt-br/hire` |
| `/hire/thanks` | `/pt-br/hire/thanks` |

Same slugs after the prefix, so `/hire/thanks` stays in the Google Ads conversion URL. No translated slugs.
Unknown addresses (in either language) get the English 404.

## Who sees which language

Language, not country: the signal is the browser's `Accept-Language`, which is what Google recommends and what covers a
Brazilian abroad and a Portuguese speaker anywhere. It runs as static redirect rules in `vercel.json` (no function, no
middleware, nothing added to an English page load):

1. Cookie `lang=pt` on an English page → 307 to its `/pt-br` twin (the visitor chose Portuguese).
2. No `lang` cookie and `Accept-Language` starting with `pt` (Portuguese is the browser's first language) → 307 to the twin.
3. Anything else → English, as is.

The language switch (nav and footer) is a plain link to the twin page that sets `lang=en|pt` (1 year), so a choice
always beats the browser. Known limit: the cookie is set by the click handler, so opening the switch in a new tab
(middle-click, context menu) doesn't save the choice, and a Portuguese browser lands back on Portuguese there. Redirects are temporary (307) and keep the query string (`gclid` from ads). `/hire/thanks`,
`/api/*`, assets and `/pt-br/*` are never redirected. Crawlers send no `Accept-Language`, so they see each URL as is.
`src/vercel.test.ts` checks the rules cover every English page in `PAGES`.

## SEO

Every page in both languages is prerendered (`vite-plugin-seo.ts`) with:
- `<html lang="en">` or `<html lang="pt-BR">`
- a self-referencing canonical (the Portuguese page is canonical for itself, never pointing to English)
- `hreflang` alternates: `en`, `pt-BR` and `x-default` (English)
- `og:locale` (`en_US` / `pt_BR`) with `og:locale:alternate`, and `inLanguage` in JSON-LD
- `sitemap.xml` lists both languages with `xhtml:link` alternates. Thank-you pages stay noindex.

## Loading

- English copy is in the main bundle, as before. English pages load nothing new.
- Portuguese copy is one separate chunk (`src/content/pt/index.ts`, dynamic import). Portuguese pages preload it with
  `<link rel="modulepreload">` in their prerendered head, and `main.tsx` waits for it before hydrating.
- If that chunk fails to load, `main.tsx` sets a session cookie `lang=en` and replaces the page with its English twin
  (`englishFallback`: the thank-you page's twin is `/hire`, so a lead is never counted twice). If it already fell back
  once this session (cookies blocked, so the redirect rules sent the visitor back), it stays on the prerendered
  Portuguese page instead, static but readable, so it can never loop.
- Each document has one language for its whole life: switching language is a full page load, never a router change.
  The router runs with `basename="/pt-br"` on Portuguese documents, so routes and `navigate()` are the same in both.

## Code

- `src/i18n/locales.ts`: the locale table (`en`, `pt`: html lang, hreflang, og locale, URL prefix), `localize(path, locale)`,
  `splitLocale(path)`, `localeFromLang()`, the cookie name. No React, so Node (the prerender, the API) can use it.
- `src/i18n/copy.tsx`: `LocaleProvider`, `useLocale()`, `useCopy()`, `useLocalize()` (for raw `<a href>` paths).
  Without a provider it is English, so tests and tools that render `<App />` alone still work.
- `src/content/*` is the English copy and the source of truth for the shape. `src/content/index.ts` exports `en` and the
  `Copy` type. `src/content/pt/` mirrors the same files and is typed `Copy`, so a missing or extra key fails `tsc`.
  Data that isn't text (slugs, image paths and sizes, logos, links, numbers) lives once, in the English files; the
  Portuguese files reuse it and translate only text.
- Components never import copy modules directly: they read `useCopy()`. `src/i18n/i18n.test.tsx` renders every
  Portuguese page and fails if English copy leaks into it, and checks the Portuguese tree has the same structure as the
  English one (same keys, same list lengths, same case-body blocks and images).

## Adding or changing copy

1. Change the English text in `src/content/...` (or add the key).
2. Make the same change in `src/content/pt/...` (`tsc` tells you where). Brazilian Portuguese, informal "você", the same
   voice as design.md §2. Facts, numbers and names stay exactly as in English (career.md is the source).
3. `npm test` and `npm run build`.

A new page: add the route once in `App.tsx` (it serves both languages) and the entry in `PAGES`; the prerender, hreflang,
sitemap and the redirect test pick it up (the test tells you if `vercel.json` needs a rule).
